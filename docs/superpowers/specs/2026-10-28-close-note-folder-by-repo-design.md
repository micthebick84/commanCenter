# 종료 노트를 레포 기준 폴더에 쓰기 — 설계

날짜: 2026-10-28 · 원 스펙: `2026-10-13-task-close-phase-design.md` §4 ③(노트)

## 1. 왜

작업 종료(kind=CLOSE)의 옵시디언 노트는 지금 레포와 상관없이 전부 `CLOSE_OBSIDIAN_VAULT_DIR` 아래 `CLOSE_NOTE_FOLDER`(기본 `HamonSoft/netisMaker`)에 쌓인다. 실제로 종료된 6건(작업 10·13·14·15·16·18)은 동부병원 대시보드·제2철도 대시보드·라이나생명 대시보드 v6.8 레포였는데 모두 netisMaker 폴더에 들어갔다.

사용자 볼트 관례(worklog 스킬 표)는 대상별로 폴더가 다르다 — netisMaker 본체는 `HamonSoft/netisMaker/`, netisweb·netis v7.0은 `HamonSoft/Netis-플랫폼공통/<제품>/`, 고객사 구축은 `HamonSoft/<고객사>/…`. 종료 노트도 대상 레포에 맞는 폴더로 가야 나중에 고객사·제품별로 찾을 수 있다.

## 2. 목표 / 비목표

목표
- 종료 노트(작업 노트 한 개)를 그 작업의 레포에 맞는 볼트 폴더에 쓴다.
- 레포 → 폴더는 **한 번 정하면 카탈로그에 기록**되어 다음 종료부터 같은 폴더를 쓰고, 관리자가 카탈로그 화면에서 보고 고칠 수 있다.
- 볼트에 이미 관련 폴더가 있으면 그 폴더를 쓴다(새 폴더를 중복으로 만들지 않는다).

비목표
- **기존 노트 6건은 옮기지 않는다.** `close_note_path`도 그대로(작업 화면 링크는 옛 경로를 계속 가리킨다). 필요하면 사람이 따로 옮긴다.
- 노트 파일 이름·프런트매터·본문 형식은 바꾸지 않는다(`{slug}-작업{id}-{date}.md`). 고객사 폴더의 `<주제> 작업정리 날짜.md` 관례로 맞추지 않는다 — 결정론 이름·재시도 덮어쓰기(멱등)를 지키기 위해서다. *(구현자 판단으로 정함)*
- 진행상황 노트를 레포별로 나누지 않는다(§4).

실패로 보는 것(기술적으로 돌아가도)
- 라이나생명 대시보드 v6.8 같은 고객사 레포의 노트가 이름에 "v6.8"이 있다는 이유로 `Netis-플랫폼공통/netisweb_v6.8`에 들어가는 것.
- 같은 레포의 노트가 종료할 때마다 다른 폴더로 흩어지는 것.

## 3. 폴더 결정 규칙 (사용자 결정)

종료 노트 폴더는 아래 순서로 정한다. 워커의 노트 단계(TaskCloser.writeNote)에서, 노트 본문 생성 전에 정한다.

1. **카탈로그에 노트 폴더가 있으면** 그 값을 쓴다(관리자가 적었거나, 예전 종료 때 자동으로 기록된 값).
2. **없으면 Claude가 볼트의 기존 폴더 중 관련 폴더를 고른다.** 후보는 볼트 `HamonSoft/` 아래 폴더 2단계까지(예: `HamonSoft/동부병원`, `HamonSoft/Netis-플랫폼공통/netisweb_v6.8`, `HamonSoft/한국가스공사/KT망`). 점(.)으로 시작하는 폴더는 뺀다. Claude에게 주는 재료: 레포 별칭, Git URL 경로(호스트·자격증명 제외), 카탈로그 설명, 작업 제목. Claude는 후보 목록의 경로 하나 또는 `NONE`만 답한다.
3. **고를 폴더가 없으면(`NONE`)** `HamonSoft/<별칭>`을 만들어 쓴다(예: `HamonSoft/라이나생명 대시보드 v6.8`).
4. **작업에 별칭조차 없으면**(`task.repo_alias`는 등록 때 박제된 값이라 카탈로그를 지워도 남는다 — 비어 있는 건 카탈로그 도입 전 작업뿐) 지금처럼 `CLOSE_NOTE_FOLDER`에 쓴다. *(구현자 판단)*

**작업의 카탈로그 찾기**는 읽기(claim의 CloseContext)·쓰기(NOTE_WRITTEN 기록) 모두 기존 `RepoCatalogRepository.findForTask`(id 먼저, 없으면 `git_url`)를 쓴다 — 카탈로그를 지웠다 다시 등록해 `repo_catalog_id`가 비어도 같은 레포로 이어진다. 카탈로그가 없으면 1은 건너뛰고(별칭으로 2·3), 기록도 하지 않는다. *(구현자 판단)*

2·3에서 정해진 폴더는 노트가 저장된 뒤 **카탈로그의 노트 폴더 칸에 기록**한다(칸이 비어 있을 때만). 그래서 2단계(Claude 선택)는 레포마다 사실상 한 번만 일어나고, 잘못 골랐으면 관리자가 카탈로그에서 고친다. 4는 카탈로그가 없으니 기록하지 않는다.

현재 카탈로그로 기대하는 결과(참고 — 실제 값은 첫 종료 때 정해진다)

| 카탈로그(id) | 기대 폴더 |
|---|---|
| 동부병원 대시보드(4) | `HamonSoft/동부병원` |
| 제2철도 대시보드(5) | 새로 `HamonSoft/제2철도 대시보드` |
| Netis7.0(3) | `HamonSoft/Netis-플랫폼공통/netis-v7.0` |
| Netis6.6/6.7/6.8(6·7·8) | `HamonSoft/Netis-플랫폼공통/netisweb_v6.6`/`_v6.7`/`_v6.8` |
| 라이나생명 대시보드 v6.8(9) | 새로 `HamonSoft/라이나생명 대시보드 v6.8` |

### 3-1. 세부 규칙

- **후보 루트** `HamonSoft`는 `CLOSE_NOTE_FOLDER`의 첫 단계로 정한다(기본값 `HamonSoft/netisMaker` → `HamonSoft`). 새 설정은 만들지 않는다. 루트 폴더가 볼트에 없으면 후보 없이 바로 3으로 간다. *(구현자 판단)*
- **Claude 호출**은 노트 본문 생성과 같은 방식(`claude.execWithoutTools`, 도구 없음, 빈 작업 폴더)으로, 모델은 `noteModel`, 시간 상한은 짧게(2분). 사용량은 종료 단계 사용량에 더한다. 프롬프트는 코드에 둔다(노트 프롬프트 템플릿 설정과 별개).
- **답 해석**: 앞뒤 공백·백틱·따옴표를 벗기고 `\`를 `/`로 바꾼 뒤 후보 목록과 정확히 같으면 그 폴더, `NONE`이면 3. 목록에 없는 답은 `NONE`으로 보고 경고 로그를 남긴다. *(구현자 판단 — 잘못 만든 새 폴더는 카탈로그에서 고칠 수 있지만, 목록에 없는 경로를 그대로 쓰면 엉뚱한 곳에 폴더가 생긴다)*
- **Claude 호출 실패**(exit≠0·시간 초과)는 노트 단계 실패로 멈춘다(종료실패 → 재시도). 새 폴더로 넘어가면 일시 장애 때문에 잘못된 폴더가 카탈로그에 굳는다. *(구현자 판단)*
- **별칭 → 폴더 이름**: 파일 시스템·위키링크에 문제 되는 문자(`\ / : * ? " < > | # ^ [ ]`)를 `-`로 바꾸고 앞뒤 공백·점을 지운다. 공백은 유지(기존 폴더 관례 `HamonSoft/경기도교육청 노후망`). 비면 4로.
- **카탈로그 값 검증**(관리 화면 저장 때와 워커 사용 때 모두): 볼트 상대 경로, `/` 구분, 빈 단계·`.`·`..` 금지, 드라이브 문자·맨 앞 `/` 금지, 500자 이하. 워커는 기존대로 정규화 후 볼트 밖이면 실패시킨다. 워커가 받은 카탈로그 값이 이 검증에 걸리면(DB를 직접 고친 경우 등) 2단계로 넘어가지 않고 **노트 단계 실패** — "노트: 카탈로그 노트 폴더 값이 잘못됐습니다: … — 레포 카탈로그에서 고친 뒤 재시도". 넘어가면 칸이 차 있어 기록도 안 되고 매번 다시 고르게 된다. *(구현자 판단)* 폴더가 볼트에 아직 없으면 만든다(관리자가 새 폴더를 적은 경우).
- **경합**: 같은 레포 작업 두 개가 동시에 종료되어 둘 다 2단계를 거칠 수 있다. 서버 기록은 조건부 UPDATE(`… SET note_folder = ? WHERE id = ? AND note_folder IS NULL`)로 해서 먼저 커밋한 값이 남게 한다(작업 행 잠금만으로는 카탈로그 행이 보호되지 않는다). 두 번째 노트가 다른 폴더에 갔을 수 있지만 드물고 무해하다고 본다.
- **관리 화면 저장과 자동 기록이 부딪히지 않게**: 카탈로그 수정 요청의 `noteFolder`는 null = 그대로 둠, `""`(공백만 포함) = 비움(다음 종료 때 다시 고르게 하려는 관리자 의도), 그 밖 = 검증 후 저장. 화면은 수정 창에서 관리자가 이 칸을 **바꿨을 때만** 값을 싣고, 활성 토글처럼 다른 칸만 보내는 요청은 null로 보낸다 — 창을 열어 둔 사이 자동 기록된 값을 빈 칸이 덮지 않게. 등록(POST)은 null/`""` 모두 비움. *(구현자 판단)*

## 4. 진행상황 노트 (사용자 결정)

`netisMaker-진행상황-{date}.md`는 **지금처럼 `CLOSE_NOTE_FOLDER` 한 곳**에 둔다. 종료 노트가 다른 폴더에 있어도 줄은 같다: `- [[노트이름]] — 작업 #id 종료(병합 sha7)`. 옵시디언 위키링크는 이름으로 찾으므로 폴더가 달라도 열린다(노트 이름에 작업 id가 있어 겹치지 않는다).

## 5. 바뀌는 곳

### 서버
- **마이그레이션 V36**: `com.repo_catalog`에 `note_folder VARCHAR(500) NULL`.
- **RepoCatalogEntry / RepoCatalogDto / RepoCatalogService / RepoCatalogController**: `noteFolder` 읽기·쓰기, 저장 때 §3-1 검증과 null/`""` 규칙. 엔티티·DTO·마이그레이션 모양은 기존 카탈로그 필드 추가(예: V35 prebuild 칸)를 따른다.
- **CloseContext**: 노트 폴더 결정 재료 추가 — `repoAlias`(task.repo_alias), `repoDescription`(카탈로그 설명), `noteFolder`(카탈로그 값, 없으면 null). claim 시점의 값을 `findForTask`로 찾아 싣는다.
- **CloseProgressRequest**: `noteFolder`(nullable) 추가 — 카탈로그에 기록할 폴더. 워커는 §3의 2·3으로 정했을 때만 싣는다(1이면 이미 기록돼 있고, 4면 기록하면 안 된다).
- **WorkerService.recordCloseProgress(NOTE_WRITTEN)**: `notePath` 저장(기존) 뒤, `noteFolder`가 있고 작업의 카탈로그(`findForTask`)가 있으면 검증 후 조건부 UPDATE로 비어 있을 때만 기록한다. 검증에 걸리면 기록만 건너뛰고 경고 로그(노트는 이미 썼으니 종료를 멈추지 않는다).

### 워커
- **TaskCloser.writeNote**: 노트 생성 전 폴더 결정(§3) → `noteWriter.write`에 노트 폴더와 진행상황 폴더(`closeProps.noteFolder()`)를 따로 넘긴다 → NOTE_WRITTEN 보고에 `notePath`와 기록할 `noteFolder`(2·3에서 정했을 때만).
- 폴더 결정은 새 클래스(예: `CloseNoteFolderResolver`)로 분리해 단위 테스트한다 — 후보 수집, 프롬프트, 답 해석, 별칭 정리.
- **CloseNoteWriter.write**: `folder` 하나 대신 노트 폴더·진행상황 폴더 두 개. 둘 다 볼트 밖이면 실패. 반환 `relativePath`는 지금처럼 **볼트 기준** 경로(`{노트 폴더}/{이름}.md`) — `close_note_path`와 작업 화면 링크가 그대로 쓴다.
- 재시도: NOTE_WRITTEN 전에 실패하면 다음 시도에서 폴더를 다시 정한다(카탈로그에 아직 기록 전). 같은 폴더가 나오면 같은 파일을 덮어쓴다. NOTE_WRITTEN 뒤 실패는 노트 단계를 건너뛰므로 영향 없다.

### 프론트
- **관리 화면 `pages/admin/repo-catalog.vue`**: "노트 폴더" 입력칸(선택). 도움말: "옵시디언 볼트 안 경로(예: HamonSoft/동부병원). 비우면 첫 작업 종료 때 자동으로 정해 여기에 기록됩니다." 목록에도 값이 보이게 한다(자동 기록을 관리자가 확인할 수 있도록).
- 작업 화면 노트 링크(`NUXT_PUBLIC_OBSIDIAN_VAULT` + `close_note_path`)는 경로를 그대로 쓰므로 바꿀 것 없음.

### 설정·문서
- `CLOSE_NOTE_FOLDER` 의미가 "모든 노트 폴더" → "진행상황 노트 폴더 겸, 레포를 알 수 없을 때의 노트 폴더 겸, 후보 루트의 기준"으로 바뀐다. `CloseProperties` 주석, `application-worker.yml` 주석, 원 스펙 §4 ③에 이 문서를 가리키는 한 줄, `CLAUDE.md`의 "종료" 항목(노트 폴더 문장)을 고친다.

## 6. 테스트

- Resolver 단위: 카탈로그 값 우선 / 후보에서 고름 / `NONE` → 별칭 폴더 / 목록에 없는 답 → 별칭 폴더 / 별칭 없음 → `CLOSE_NOTE_FOLDER` / Claude 실패 → 예외 / 별칭 문자 정리 / 점 폴더·3단계 이하 제외 / 루트 없음.
- CloseNoteWriter: 노트와 진행상황이 서로 다른 폴더에 쓰이고, 진행상황 줄 형식이 같다.
- TaskCloser: NOTE_WRITTEN 보고에 `noteFolder`가 2·3일 때만 실린다, 사용량 합산.
- WorkerService: 칸이 비었을 때만 기록, 이미 있으면 그대로, `repo_catalog_id`가 비어도 `git_url`로 찾아 기록, 검증 실패 값은 400 아님(노트는 이미 썼으니 기록만 건너뛰고 경고) *(구현자 판단 — 종료를 멈출 이유가 아니다)*.
- Resolver: 카탈로그 값이 검증에 걸리면 예외(노트 단계 실패).
- 카탈로그 API: 저장·검증, 수정 때 null=유지·`""`=비움.
- 프론트 vitest: 관리 화면 입력·표시.

## 7. 배포

DB 마이그레이션(V36)과 서버·워커·프론트를 함께 바꾼다. 서버와 워커가 같은 PC에서 같은 빌드로 뜨므로 한 번에 재기동한다. 순서·확인 방법은 PR 본문에 적는다. 첫 확인: 다음 종료 작업(예: 라이나생명 레포)의 노트가 기대 폴더에 생기고 카탈로그 칸이 채워지는지.
