## 2. 목표 / 비목표

**목표 (모바일, lt.md)**
1. 첫 화면에서 "내 작업이 지금 어느 단계이고, 다음에 누가 무엇을 해야 하는가"가 보인다.
2. 스크롤 축은 세로 하나. 가로 오버플로 0(`scrollWidth == innerWidth`).
3. 모든 탭 타깃 ≥ 44px. 관리자 전이(승인·배포·재배포·중지)를 터치로 수행할 수 있다.
4. 다이얼로그는 화면 안에 들어온다(전체화면 시트).
5. 데스크톱 레이아웃·동작 무변경. 기존 `taskStages.ts`(단계·색·전이 정의)를 재사용해 두 레이아웃의 의미가 어긋나지 않게 한다.

**비목표**: 새 상태/전이 추가, 작업 등록 폼 필드 변경, 알림/푸시.

## 3. 접근 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 현행 보드 반응형 보정 | lt.md에서 요약 패널을 위로, 카드 트랙을 세로 스택으로, 빈 단계 접기 | 변경 최소, 단계 멘탈모델 유지 | 여전히 5단계 블록을 훑어야 "내 작업"에 도달. 관리자 전이 수단 없음. 진행 상황 질의에 최적화되지 않음 |
| **B. 주의 필요 우선 단일 리스트 (추천)** | lt.md에서 보드 대신 세로 카드 리스트. "확인 필요 → 진행 중 → 완료 → 취소" 순 정렬, 필터 칩, 카드에 4단계 스테퍼, ⋮ 액션 시트(전이 포함), FAB 등록 | "지금 뭘 해야 하나"가 최상단. 한 축 스크롤. 전이 복원. 요청자(작업 2~3건)에게 군더더기 없음 | 모바일 전용 컴포넌트 신설(레이아웃 2종 유지 — 단계/색/전이는 `taskStages.ts` 공유로 완화) |
| C. 단계 아코디언 | 분석/디자인/구현/배포를 접이식 섹션으로, 빈 단계는 한 줄 헤더 | 단계 그룹 유지, 한 축 스크롤 | 확인 필요 작업이 단계 안에 묻힘. 탭 수 증가. 요청자에겐 과한 구조 |

**선택: B.** 이유 — 사용자의 요구가 "작업 진행 상황 보기"이고, 모바일 방문 동기는 대부분 (a) 내 요청이 어디까지 왔나 (b) 내가 답/승인해야 할 게 있나 이다. B는 두 질문을 카드 정렬과 스테퍼로 직접 답한다. C의 단계 묶음은 데스크톱 보드가 이미 제공하므로 모바일에서는 "단계별 보기" 토글로 후속 추가 가능(이번 범위 밖, YAGNI).

- **정렬(그룹 → updatedAt desc)** — 순수 함수 `attentionGroup(task, isAdmin)`로 정의하고 표 기반 단위 테스트:
  1. **확인 필요**: `INTERVIEW_INPUT`(입력대기), `INTERVIEW_REVIEW`(플랜승인대기), 관리자면 `AWAITING_APPROVAL`·`COMPLETED`·`DESIGN_REVIEW`, 실패 계열(`FAILED`·`IMPLEMENTATION_FAILED`·`DESIGN_FAILED`·`DEPLOY_FAILED`·`DEPLOY_LOST`)
  2. **진행 중**: `INTERVIEWING`·`PENDING`·`IN_PROGRESS`·`APPROVED`·`IMPLEMENTING`·`DESIGN_PENDING`·`DESIGNING`·`DEPLOY_PENDING`·`DEPLOYING`·`UNDEPLOY_PENDING`·`UNDEPLOYING` (+ 요청자에게는 `AWAITING_APPROVAL`·`COMPLETED`·`DESIGN_REVIEW`)
  3. **완료/산출**: `PR_CREATED`·`DEPLOYED`
  4. **취소됨**: `CANCELLED` (기본 접힘, 건수만)
- **필터 칩**: 전체 · 확인 필요 · 진행 중 · 완료 · 취소(칩=그룹). 현행 14개 상태 select는 `⋯` 시트로 이동(데스크톱은 그대로). `내 작업만`은 토글 유지(관리자 기본 ON 현행 유지).
- **카드**: 탭 → 상세. `⋮` → **액션 시트**(하단 시트, 44px 행): 상세 보기 / (관리자) `taskStages.MOVES` 허용 전이(승인 — 구현 큐 진입·디자인 승인·배포·재배포·중지; `confirm:true`는 확인 다이얼로그 유지) / 취소(현행 `cancelable`) / 삭제(배포 활성이면 비활성 + 이유). 드래그는 데스크톱 전용으로 남기고 하단 드래그 안내문은 lt.md에서 숨김.
- **스테퍼**: `buildStages`의 `steps`(분석·디자인·구현·배포, 현재 단계 색·이전 단계 연녹·이후 회색) 재사용. 4세그먼트 + 현재 단계명 텍스트. 디자인 미요청 작업은 디자인 세그먼트를 점선(건너뜀)으로.
- **"다음 할 일" 한 줄**: §4.2의 `nextAction(task, isAdmin)` 문구를 카드에도 노출(있을 때만).
- **요약 스트립**: lt.md에서 `QueueStatsBar` 22타일 대신 그룹 3숫자(확인 필요·진행 중·완료). 관리자는 탭으로 22타일 펼침(`q-expansion-item`). 데스크톱 무변경.
- 빈 상태: "등록된 작업이 없습니다 — (+)로 첫 작업을 등록하세요". 폴링·낙관적 갱신은 현행 `useTaskPolling` 그대로.

### 4.2 작업 상세

```
┌──────────────────────────────────────┐
│ ‹ 작업 목록                           │
│ 장비 현황 화면 개발              #18 │  ← 제목 2줄 클램프
│ ● PR생성 · 13일 전 갱신               │
│ ┌──────────────────────────────────┐ │
│ │ ✔ 분석 ─ ○ 디자인 ─ ● 구현 ─ ○ 배포 │ │  ← 진행 스테퍼(현재 단계 강조, 건너뜀 점선)
│ │   PR생성 · PR #13 ↗                │ │  ← 현재 세부 상태 + 핵심 산출물 링크
│ └──────────────────────────────────┘ │
│ ▸ 진행 이력 14건            (아코디언) │  ← task_status_history 타임라인(§6)
│ ▸ 요청 상세 · Netis7.0 · main         │
│ ▸ 분석 결과 (마크다운, 6줄 미리보기 · 전체 보기) │
│ ▸ 디자인 문서 (마크다운, 6줄 미리보기 · 전체 보기) │
│ ▸ 구현 결과 · PR #13 · 브랜치         │
│ ▸ 배포 · URL · 로그                   │
│ ▸ 지난 인터뷰 4건                     │
│ ▸ 정보: opus-5 · high · 123k 토큰 · $0.42 · MCP · 첨부 │
├──────────────────────────────────────┤
│ [ 🚀 배포 ]                    [ ⋮ ]  │  ← 하단 고정 액션 바(주 행동 1 + 보조 메뉴)
└──────────────────────────────────────┘
```

- **진행 스테퍼**: `TaskProgressStepper` — 단계 4 + 현재 세부 상태 라벨(`statusLabel`) + 마지막 갱신(`updatedAt` 상대시간). 실패 상태는 해당 단계를 빨간 표시 + 실패 사유 1줄.
- **다음 할 일 / 하단 액션 바** — 순수 함수 `nextAction(task, isAdmin)` → `{ text, primary?: {label, icon, kind}, secondary?: [...] }`:

| 상태 | 요청자 문구 | 관리자 문구 / 주 행동 |
|---|---|---|
| AWAITING_APPROVAL | 관리자 승인을 기다리는 중 (취소 가능) | **승인 — 인터뷰 시작**(ApproveDialog) |
| INTERVIEWING / IN_PROGRESS / IMPLEMENTING / DESIGNING / DEPLOYING | 진행 중 — 완료되면 상태가 바뀝니다 | 같음 (+ 인터뷰는 **대화 열기**) |
| INTERVIEW_INPUT | (관리자 답변 대기) | **답변하기** → 인터뷰 패널 |
| INTERVIEW_REVIEW | 플랜 검토 중 | **플랜 확인 → 구현 진행** → 인터뷰 패널 확정 |
| COMPLETED | 분석 완료 — 관리자 승인 대기 | **구현 승인** |
| DESIGN_REVIEW | 디자인 검토 중 | **디자인 승인 / 피드백** |
| PR_CREATED | **PR 열기** | **배포**(환경변수 시트) + PR 열기 |
| DEPLOYED | **접속 URL 열기** | 접속 URL 열기 + 재배포 · 중지 |
| FAILED / DESIGN_FAILED | 실패 — 사유 확인 | **재시도**(현행 한도 규칙) |
| IMPLEMENTATION_FAILED / DEPLOY_FAILED / DEPLOY_LOST | 실패 — 사유 확인 | 재배포(배포 계열) / 사유 확인 |
| CANCELLED | 취소됨 | — |

  주 행동 1개만 하단 바에 크게, 나머지는 `⋮`(취소·삭제·PR·URL·대화 열기). 데스크톱은 현행 카드 내 버튼 유지(같은 `nextAction`을 쓰되 렌더 위치만 다름).
- **섹션 아코디언**(`q-expansion-item`) 기본 상태: 진행 이력 접힘(건수 표시), 요청 상세 접힘, 결과/배포는 현재 단계에 해당하면 펼침, 나머지 접힘.
- **마크다운**: `useMarkdown`으로 렌더(현재는 원문 `pre`). 6줄 미리보기 + "전체 보기" → 전체화면 `MarkdownViewerDialog`(제목·닫기·복사). 컨테이너 `max-width:100%; overflow-x:auto`로 표/긴 줄을 **컨테이너 안에서만** 스크롤 → D1 해소(`scrollWidth == innerWidth` 어서션).
- **정보 아코디언**: 모델·effort·토큰/비용·MCP 스냅샷·첨부파일(다운로드)·요청자.
- 인터뷰 패널(`InterviewPanel`)은 인터뷰 단계에서만 인라인(현행)이되, 모바일에서는 "대화 열기" → 전체화면 시트로 여는 것을 기본으로 한다(입력창이 하단 액션 바와 겹치지 않게).

### 4.3 다이얼로그 → 모바일 전체화면 시트

공통 규칙: `:maximized="$q.screen.lt.md"`, 고정 `min-width` 제거(`width: min(520px, 100vw)`), 액션 버튼은 하단 고정 full-width 44px, 스크롤은 카드 본문만. 적용 대상(이번 범위): 작업 등록, 배포 환경변수, `ApproveDialog`, `DesignReviewCard` 피드백, `InterviewHistoryDialog`. `q-dialog` 콘텐츠 루트는 `<div>`(CLAUDE.md 규칙).

### 4.4 전역 내비게이션 (lt.md) — 하단 내비 바

```
┌──────────────────────────────────────┐
│ netisMaker                  ADMIN ⎋  │  ← 헤더: 브랜드 + 사용자 칩 + 로그아웃 (탭 제거)
│ …페이지 본문…                        │
├──────────────────────────────────────┤
│   ▣ 작업      ✎ 질문      ⚙ 관리     │  ← QFooter + q-tabs(q-route-tab), 56px + safe-area
└──────────────────────────────────────┘
```

- 헤더 `q-tabs`는 lt.md에서 숨기고 `QFooter` 안의 `q-tabs`(`q-route-tab`)로 옮긴다. 항목: **작업**(`/tasks`) · **질문**(`/questions`) · 관리자만 **관리**(`/admin/workers`, 활성 판정은 `/admin/*` 전체). 워커 헬스·MCP 카탈로그·레포 카탈로그는 `/admin/*` 페이지 상단의 세그먼트 탭 1줄로 오간다(이번 슬라이스 범위).
- 높이 56px + `env(safe-area-inset-bottom)`. 본문 하단 여백은 Quasar `q-layout view="hHh lpR fFf"`의 fixed footer가 자동 처리. 질문 대화 페이지의 입력창·사용량 스트립과 작업 상세의 하단 고정 액션 바는 **내비 바 위에** 쌓인다(액션 바 `bottom` = 내비 높이).
- 데스크톱(≥md)은 현행 헤더 탭 그대로, 푸터 없음. 배지(확인 필요 건수)는 후속(YAGNI).
